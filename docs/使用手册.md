## 2. DMAC 的约定

所有通道独立，时钟为 `clk`，低有效异步复位为 `rst_n`。host 读命令将内存数据送到 device；host 写命令将 device 数据写入内存。两方向可并发。

| 接口 | 输入 DMAC | 输出 DMAC |
| --- | --- | --- |
| host 读 | `host_rd_req`、`host_rd_haddr[ADDR_W-1:0]`、`host_rd_len[LEN_W-1:0]` | `host_rd_ack`、`host_rd_done` |
| host 写 | `host_wr_req`、`host_wr_haddr[ADDR_W-1:0]`、`host_wr_len[LEN_W-1:0]` | `host_wr_ack`、`host_wr_done` |
| mem 读 | `mem_rd_ready`、`mem_rd_data[63:0]` | `mem_rd_valid`、`mem_rd_addr[ADDR_W-1:0]` |
| mem 写 | `mem_wr_ready` | `mem_wr_valid`、`mem_wr_addr[ADDR_W-1:0]`、`mem_wr_data[63:0]` |
| device 读 | `dev_rd_req` | `dev_rd_ack`、`dev_rd_data[15:0]` |
| device 写 | `dev_wr_req`、`dev_wr_data[15:0]` | `dev_wr_ack` |

host 在请求与确认同拍接受命令。`len` 表示内存拍数减一：0 表示一拍，1 表示两拍；设备拍数为内存拍数的四倍。长度计数在扩展位宽中计算，不能让最大值加一溢出。没有 8 字节地址对齐或长度为字节倍数的限制；mem 地址直接从对应 haddr 起步，每次内存握手后加 8，按地址位宽自然回绕。内存端负责支持该地址访问。

mem 在 `valid && ready` 时握手；读数据在同一个采样沿已就绪。device 在 `req && ack` 时传递一个 16 位片段，顺序为 `[15:0]`、`[31:16]`、`[47:32]`、`[63:48]`。因为最终长度以完整 64 位内存拍计数，本规格没有奇数字节末拍。具体稳定性、复位和完成时机以规格及对应 CK 为准。

## 3. 下载与离线查看

仓库源码和历史证据可通过 GitHub Desktop 克隆，或使用 **Code → Download ZIP** 获取。要在新设备开箱运行，请下载 Release 中的完整离线 `.tar.gz`；源码 ZIP 不含完整运行时。

用浏览器打开 `verification/reports/testpoints.html`。页面为中文，可筛选证据来源、实际结论、需求、检测点、参数或运行编号；故障修改版默认隐藏，可勾选显示。点击运行清单查看对应原始结果。GitHub 网页上的 HTML 源码预览不会运行交互脚本。

在仓库根目录执行：

```sh
python3 scripts/check_delivery.py
```

`DELIVERY_SHA256.json` 检查交付文件；`ucagent-tool/SOURCE_SNAPSHOT.json` 关联实际运行的工具源文件；报告目录的清单和翻译记录保留原包与中文展示的差异。修改交付输入后应建立新版本、重新运行并生成新证据。

## 4. 不调用模型的重跑

完整离线版解压后直接运行 `./Run-DMAC --suite all`，工具和 Python 已随包提供。以下命令仅用于源码开发部署：需要 Linux、Python 3.8+、SBY、Yosys、yosys-smtbmc、Z3、Icarus Verilog 与 vvp，可将已安装的 OSS CAD Suite 的 `bin` 加入 PATH。仓库源码不存放这些大型二进制；Release 离线包包含它们。

```sh
export PATH=/opt/oss-cad-suite/bin:$PATH
python3 scripts/run_dmac.py --suite smoke
python3 scripts/run_dmac.py --suite native
python3 scripts/run_dmac.py --suite guided
python3 scripts/run_dmac.py --suite replay
```

| 选项 | 实际执行范围 |
| --- | --- |
| `smoke` | 32/1/4 安全证明、地址步进故障对照、全部 19 次实际回放 |
| `native` | 四组安全证明、五组覆盖、七项故障对照，共 16 个任务 |
| `guided` | 主任务当前固定输入的深度 12 有界检查与覆盖运行 |
| `replay` | 七次修改版反例匹配、七次原版区分对照、五次原始业务覆盖回放 |
| `all` | 上述全部，去除重复项；不默认重复执行已知超时的联合无界证明 |

也可显式指定工具路径：

```sh
python3 scripts/run_dmac.py --suite smoke \
  --sby /opt/oss-cad-suite/bin/sby \
  --iverilog /usr/local/bin/iverilog --vvp /usr/local/bin/vvp
```

每次运行生成 `results/时间-随机编号/`，保存精确配置、复制的输入、命令、日志、波形和 `results.json`。工具版本记录在本次结果目录中。无工具、超时、编译错误或缺少状态文件不能成为通过。

故障对照要求真实断言失败及反例轨迹；原版对照要求实际发生 `VECTOR_MISMATCH`，因此这些原版对照仿真返回码 1 是预期区分结果。其余回放要求返回码 0 和实际 `PASS replay` 标记。重跑脚本的返回码 0 只表示该范围产生了预期证据，不能把有界无反例或部分覆盖改称完全获证。

## 5. 部署 UCAgent 后端

后端需要 Python 3.11+。在普通 Linux 用户下操作；执行服务拒绝以 root 运行。建议在新目录创建虚拟环境，不改现有 UCAgent 安装。

```sh
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ./ucagent-tool
python -m pip install pytest
```

仓库另提供在 VM 构建的 `bin/ucagent-0.9.1-py3-none-any.whl`，也可用 `python -m pip install bin/ucagent-0.9.1-py3-none-any.whl` 安装。其 0.9.1 是源码构建的回退版本号；具体改动与身份以源码快照哈希为准。安装依赖和 EDA 工具仍由目标设备提供。

依赖列表见 `ucagent-tool/pyproject.toml`，安装需要访问其依赖源。已存在兼容环境时也可以用 `PYTHONPATH` 指向 `ucagent-tool/` 运行；不需要为单独执行第 4 节的重跑脚本安装这些后端依赖。

复制 `config/toolchains.sby.example.yaml` 为 `config/toolchains.local.yaml`，将示例 `/opt/oss-cad-suite` 改为实际路径。随后在仓库根目录启动：

```sh
python -m ucagent.server.platform_main \
  --workspace "$PWD/state" --import-root "$PWD" \
  --toolchains "$PWD/config/toolchains.local.yaml" \
  --host 127.0.0.1 --port 8800
```

`state/` 为新的服务数据目录。它不包含历史机器的签名密钥和数据库，不会恢复原设备上的已完成审批。服务的运行、工程导入与证据都以新设备为准。

## 6. 桌面客户端与工程导入

客户端需要 Python 3.8+ 和 Tkinter；Windows 本机与 Linux 桌面均可启动：

```sh
python bin/UCAgent-Desktop.pyz --server http://127.0.0.1:8800
```

也可启动 `ucagent-tool/desktop/ucagent_app.py`，或用 `python ucagent-tool/desktop/build.py` 重新构建客户端。客户端仅依赖 Python 标准库，不含后端与求解器。

若服务部署在远程设备，先建立 SSH 转发，保持终端运行：

```sh
ssh -N -L 8800:127.0.0.1:8800 用户名@执行设备
```

在客户端连接 `http://127.0.0.1:8800`。导入路径始终是**服务所在设备**上的路径，并必须落在 `--import-root` 范围内。

仓库提供两个已有工程配置：

| 工程目录 | 用途 |
| --- | --- |
| `projects/DMAC-native` | 已有原生 harness，可直接导入并执行 SBY；初始状态为尚未运行 |
| `projects/DMAC-guided` | 原始 RTL 和需求，用于新建完整形式化阶段任务；直接 EDA 运行前须生成 checker/wrapper |

在“项目”中点击“导入工程”，选择其中一个目录。`DMAC-native` 可用“新建运行”直接运行已有环境。这不是自动完成 14 阶段的入口。需要完整流程时使用 `DMAC-guided` 的“形式化工作台”，明确选择 SBY 后开始新的阶段任务。

仓库中的历史报告是可审计交付，不是可直接载入的服务数据库。新的完整任务可参考 `verification/reports/guided/.formal_records.yaml`，但不能通过复制历史完成标记省略门禁。

## 7. 完整的 14 阶段操作

启用的阶段依次为：需求分析与验证规划、设计功能理解与接口分析、功能分组、功能点分解、检测点设计、功能规格汇总、属性生成与审查、验证脚本生成与执行、环境调试与约束审查、覆盖分析与缺口审查、反例测试分支、验证结果与缺陷报告、静态源码审查与证据关联、验收审查与验证总结。

启动 Agent 需要在执行端单独配置已安装的模型/CLI 后端和账号。仅查看证据、直接跑已有 harness 和第 4 节重跑不调用模型。账号配置存于私有环境或执行端用户配置，不能写入此公开工程。

每阶段操作：先阅读阶段要求，保存草稿，检查差异，执行 **Check**，处理失败诊断，再执行 **Complete**。遇到人工审核门禁，根据具体规格、约束与求解结果审查；不能因为需要推进进度就批准。运行后检查模式、参数、输入哈希、逐属性状态及覆盖轨迹，再进行总结。

本轮参考规格形成 R01–R14、12 个 FG、48 个 FC 和 88 个 CK。完整表达式、guard、历史有效条件与需求映射都在属性记录中。首个采样点建立复位初态；之后允许再次复位。组合、时序、Assume、Cover 与触发见证应分别检查，不增加对地址、长度、数据或永久背压的隐含约束。

前序 Agent 的上下文限制和运行缓存缺陷触发工程恢复。本轮明确记录了 Agent 与工程师的分工，新恢复任务重新执行原生门禁，没有将人工接续标为纯 Agent 自动执行。新机器发生异常时保留任务记录，使用恢复入口，不手工改完成状态。

## 9. FormalMC 内部迁移

SBY 任务和原始 FormalMC 工作流保留各自运行历史。内部迁移是固定源输入版本、转换属性与编译依赖，创建新的 FormalMC 工程，再用目标设备的真实工具链运行；不要求用户先导出 ZIP 再导入。

在 SBY 工作台的迁移入口核对当前版本、保存状态与源运行证据。迁移前应检查 RTL、属性、宏、参数、源文件与 include 顺序、复位与历史条件的转换报告。输入已变化或依赖不全应修复后重试。目标工程初始结果为尚未运行，不继承 SBY 通过结论、审批或完成阶段。

目标设备的管理员配置已安装 FormalMC 工具链与许可证，参考 `ucagent-tool/deploy/toolchains.formalmc.example.yaml`。转换后仍须实际编译、求解、检查逐属性结果和反例；未知结果、工具超时或许可证错误不能算通过。本轮没有 FormalMC/VCS 设备实测，因此这里只交付现有代码与说明，不宣称商业工具已验收。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| 报告中文但日志仍有英文 | 机器原始记录保留原样，中文页面解释实际状态 |
| SBY 输出 PASS，但主报告仍未决 | 有界检查的 PASS 仅覆盖指定深度；不能当成无界证明 |
| Cover 返回 FAIL | 查看命中与未命中目标；未命中不是已证明不可达 |
| 工程导入找不到路径 | 核对服务端路径和 `--import-root`，不是本机客户端路径 |
| 初次导入没有历史已完成任务 | 本包不发布服务数据库；新设备必须产生新任务与审批 |
| 缺少 Tkinter | 安装当前 Python 对应的 Tk 支持；纯 SSH 无桌面只能使用重跑脚本 |
| 缺少求解器或许可证 | 配置实际安装；不要通过更改结果状态绕过错误 |
| 清单校验失败 | 查看列出的缺失/变化文件，重新下载完整版本或建立新版本验证 |
