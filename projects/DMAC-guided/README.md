## 4. 形式化验证范围与目标

### 4.1 纳入验证范围

- 默认参数 32/32/2 下全部 26 个端口的方向、位宽、握手和双向独立行为
- host 命令接受、锁存、忙时等待、完成脉冲以及连续命令
- 任意起始地址、每次实际内存握手后地址加 8 和 32 位自然回绕
- len 表示内存拍数减一，所有 32 位模式合法，内存拍数为 len+1，设备拍数为 4 倍
- 内存背压稳定性、低 16 位片段优先的数据拆分与拼接、端到端数据顺序
- FIFO 空满、顺序、同拍入出队、满时替换，并以原生辅助参数实例检查深度 1 和非二次幂深度
- 低有效异步复位，包括初始复位和传输中再次复位，以及复位后无残留
- 双向并发、连续至少三条突发、待处理 host 请求、可达覆盖和有条件的局部前进
- 故障对照、真实动态反例回放分支和静态线索与形式结果关联分支


### 4.2 暂不纳入验证范围

- 综合、时序收敛、跨时钟域以及规格不存在的 busy、status、dev_fixed、字节使能或独立响应通道
- 无公平性前提下永久背压场景的最终完成保证
- SBY 不支持的自动白盒导出、完整并发 SVA、COI、无界活性和完整空洞性证明

## 6. 验证策略

- 先从 README 和两个 RTL 建立 R01 至 R14 的需求追踪，再完成接口理解；本轮在 FG 分组前停下由工程师审查规划与接口。
- 主任务引导式（guided）环境只使用 DUT 顶层可见端口，承担接口连接、外部可观察控制与握手安全属性、协议 Assume 和业务 Cover；不得层次引用、注入 RTL 或编造白盒导出支持。
- 原生辅助（native）环境由工程师独立运行，承担完整数据记分板、FIFO 内部模型、任意 32 位 len 的扩展计数与配额等白盒或长状态义务；其属性和结果使用 native 命名空间，不冒充主任务结果。
- 安全性使用 prove；业务可达性另行运行 cover。若改用 bmc，则无反例仍记为未决；Cover 命中只证明探针可达，不能替代正确性证明或 COI。
- 复位、背压和历史采样条件逐项显式建模；不以地址对齐、len 子集、有限背压或数据约束换取通过。
- 对 falsified 属性先核查环境和当前输入签名，再保留真实 RTL 缺陷；启用的反例动态回放与静态关联分支无 Bug 时也走完明确的无 Bug 路径。
- 最终统一需求表按 R→FG→FC→CK→属性身份→当前签名运行结果追踪，并分别标注 guided 主任务与 native 辅助工程的已证明、仅覆盖、未决或不支持结论。

## 8. 风险评估与应对

- 风险：guided 自动路径不支持白盒导出，若缺少工程师提供的 native 当前签名证据，完整数据、FIFO 和任意长度计数义务必须保持未决。

- 风险：LEN_W=32 的全长度空间无法靠有界展开穷举；必须依赖正确的扩展计数不变量与归纳证明，bmc 无反例不能升级为证明。

- 风险：永久背压合法，因此无公平性时最终完成不是可证明要求；局部前进和 Cover 需避免混同无界活性。

- 风险：异步复位可在传输中重入；遗漏复位边界或历史有效条件会制造伪反例或掩盖残留状态。

- 风险：FIFO 深度 1 和非二次幂检查属于独立 native 参数辅助工程，不能冒充默认参数主任务签名。

- 风险：Cover 和 guard witness 不能替代 COI 或完整空洞性分析；本引擎的 COI 不支持，vacuity 与 liveness 未建立。

- 风险：反例仅在实际动态运行成功且症状一致后才算复现；静态线索在无形式反例时不能仅据无反例判为误报。
