
# 形式化 GUI 阶段工作台

本工作台把原始形式化阶段生命周期接入 Tk。SBY 和 FormalMC 使用相同的
创建、启动/继续 Agent、读取、编辑、检查、完成、审核和恢复操作；只在创建时选一次引擎。
不代表两种引擎的属性语法和证明能力相同。
客户端只需要 Python 3.8+ 与 Tk，执行服务使用独立 Python 3.11+。

## 入口与任务创建

1. 启动执行服务及匹配版本的 Tk 客户端。通过“连接”填写服务地址。
2. 在“项目”导入包含 RTL 和规格的服务器目录。
3. 进入“形式化工作台”，点击“新建阶段任务”。不要使用面向已有 harness 的“新建运行”。
4. 选择项目，填写真实 DUT 模块名，明确选择 `formalmc` 或 `sby`。
5. SBY 的工具链 ID 对应执行用户 `~/.ucagent/toolchains.yaml` 中的 profile；
   FormalMC 沿用原始工具环境，不会因选了某个 SBY profile 而自动切换引擎。
6. 明确是否启用人工审核、反例复现和静态缺陷关联。创建后这些选择固定；
   改引擎或分支组合需要创建新任务，不把旧进度套到新流程上。

服务复制有界 RTL/文档输入到独立工作目录，保留原工程不变。
不复制旧 `.ucagent`、旧证据、凭据、自动执行配置或大型数据库。
输入放在 `{DUT}/` 下，保留工程内部相对目录；记录中的 source 路径以工作目录为基准。

## 每阶段操作

左侧始终显示 11 个主阶段及规格分析的 3 个子阶段。关闭的反例与静态分支
仍可选中查看原因。选择树节点只查看任务，不会跳过或推进当前阶段。

日常首选“Agent 工作台”：输入本轮目标，确认模型交互轮数和超时，点击
“启动 / 继续 Agent”。两种引擎共用同一个受限 Claude Code 驱动、会话恢复和阶段工具：
`RoleInfo`、`CurrentTips`、`ReadTextFile`、`EditTextFile`、`Check`、`Complete`、
`SetCurrentStageJournal`。Agent 读取真实阶段要求，准备当前产物，执行检查，
遇到人工门禁后停止。检查结果、编辑差异与工具事件可在对应页签查看。

审核当前文件和检查结果后，在“日志与审核”中填写审核意见并点击“审核通过”，
再回到 Agent 工作台点击“启动 / 继续 Agent”。后台恢复明确的同一个会话 ID，
重新读取持久化阶段，不使用“最近一次会话”或从 AI 回复推断进度。
Agent 没有审核、跳阶段、通用 Shell 或修改原始 RTL 的工具权限。
连续三次检查未通过后转人工处理；轮数和超时到达不表示验证通过。

需要人工接管时，两种引擎使用以下同一组高级操作：

1. 阅读“阶段要求”页签；双击下方输入文件逐个读取。
   列表中的未读状态由真实文件读取操作更新，不是一个“全部已读”复选框。
2. 在“输入与产物编辑”读取 `formal_out/.formal_records.yaml`。
   按当前阶段填写 planning、basic_info、spec、extra_config、analysis、bugs、summary。
   文件契约以任务中的 `Guide_Doc` 为准；编辑器不是 golden model 生成器。
3. 点击“审查差异并保存”，审查逐行差异，再确认保存。
   保存携带读取时的 SHA-256；内容已被其他操作修改则拒绝覆盖。
4. 在“日志与审核”页签填写阶段日志，点击“检查 Check”。检查结果显示准确失败输入与修复建议。
   Check 可以处理当前批次，但不直接完成整个阶段。
5. 若启用人工审核，审阅当前产物后填写意见并点击“审核通过”或“退回修改”。
6. 点击“完成并推进”。原始 Complete 会再次运行检查、核对日志及审核门禁。
   不满足条件时留在原阶段；完成标记不能由界面直接设置。

SBY 的 checker、wrapper、`.sby`、运行清单和覆盖数据由确定性工具生成。
`run_results` 是工具字段，不能在编辑器里手填“通过”。需要额外的反例测试
时可使用“新建文件”建立 `formal_out/tests/` 下的测试文件，仍需真实运行证据。

## 结果、能力与证据

| 项目 | SBY 接入 | 原始 FormalMC 接入 |
|---|---|---|
| 属性语法 | Yosys 原生表达式；不是完整并发 SVA | 原始 SVA/Tcl，具体支持依工具版本 |
| COI | 不支持，不用 Cover 百分比替代 | 必须有真实 fanin 报告 |
| 空洞性 | guard/trigger Cover 仅作可达见证，不是完整空洞检查 | 依实际 TRIVIALLY_TRUE 等报告与约束审查 |
| 活性 | 未建立无界活性能力 | 依工具、属性及实际证明结果 |
| BMC | 无反例仍为 inconclusive | 不将有界结果称为无界证明 |
| 动态反例 | 只有实际测试执行证据才表示复现 | 同样保留原始真实执行门禁 |

阶段完成不等于 DUT 通过。“检查结果与事件”分别显示执行状态、最近验证结论、
实际 Checker 诊断和能力范围。SBY 的 proven/falsified/inconclusive 结论来自签名
运行清单；未实跑的 FormalMC 能力不能由 SBY 结果认证，界面不会自动切换工具。
仅原始报告、没有规范化签名证据时，汇总验证结论保留 unknown，原始检查结果仍可查看。

SBY 日志事件由 JobRunner 提供，带持久化递增游标，重连只读取缺失事件。
在文件选择器中选择实际日志、VCD 或其他文件，点击“下载”，客户端流式传输并
校验大小和 SHA-256。下载不代表未经签名验证的文件自动成为验收证据。

## 暂停、恢复、重试与重开

- 空闲时“暂停”；随后“恢复”回到同一阶段。暂停不制造证明结果。
- 检查运行时可“停止检查”。必须等实际检查停止后才允许编辑；已生成文件保留。
- 修正当前输入后再次 Check，即为重试。网络错误不自动重发修改请求。
- 选中已到达阶段后“重开所选阶段”，明确确认后清除该阶段及后续完成状态，
  保留原文件、日志和证据。未来阶段不能直接跳转。
- 修改较早记录字段，会使其所属阶段及后续完成状态失效。例如改 planning
  返回规划阶段；修改 FG 元数据回到分组，修改 FC 定义回到功能点，修改 CK 要求回到检测点，
  仅修改属性表达式、guard 或 trigger 回到属性生成。填写当前层级不撤销未变的上游阶段；
  删除或移动条目仍需重新审查其所属层级。改环境配置返回脚本阶段。
- 关闭客户端不停止服务。重新打开任务可恢复阶段、已保存日志、审核意见和结果。
- 服务重启时，未结束操作标记为中断并暂停，需明确恢复和重新检查，不自动补发。

服务从签名的持久化原始阶段快照恢复，不信任工作目录中手写的进度标记。
若在编辑器外修改已绑定输入，保存的阶段完成状态不再可信；保留修改文件并创建
新任务重新验证。历史 Run 不转换成新的阶段完成证据。

## 共用 Agent 部署与实施范围

管理员配置一个含 `claude` 可执行文件别名的主机 profile，并指定执行用户的
`HOME`，示例见仓库 `deploy/toolchains.formal-agent.example.yaml`。
执行用户的私有 `~/.claude/settings.json` 必须已配置可用连接；
Linux 下该文件须由执行用户所有且仅本人可读写（0600）。不得把凭据放入工程或工具链 YAML。
可在该主机 profile 设置非秘密字段 `claude_model: gpt-5.6-sol`，仅为使用此工具链文件的
实例固定模型；省略时私有设置必须明确指定模型。此字段不会修改私有设置，连接凭据仍只从
执行身份的私有设置读取。已有 Agent 任务不能跨模型恢复，切换模型后需新建阶段任务。
未配置时，两种引擎都明确阻止 Agent 启动，人工阶段操作仍可用。

点击启动会调用已配置的 AI 服务，预算确认不是零费用承诺。
CLI 由 JobRunner 管理，使用参数数组、独立 Claude 资源队列和有界会话；
禁用通用内置工具、项目 hooks、插件及其他 MCP 服务。
受限 MCP 使用仅本轮有效的认证令牌；配置文件只写环境变量占位符，
不复制 Claude 登录凭据到项目或数据库。

原有 Agent 的 CLI/TUI/MCP 自动编写入口继续存在；
不要同时对同一个受管工作目录运行第二个 Agent 或阶段管理器。
工作台仍是单用户研发工具，不提供不可信 HDL/Python/Tcl 的多租户安全沙箱。

FormalMC 真实工具验收需要本机安装和合法可用许可；其阶段入口可用，不表示
该工具已经在未安装的机器上通过实跑。反例复现与静态关联是否实测应逐项记录，
不能用关闭分支的主流程验收代替。


## 导出可搬运 FormalMC 工程

已实际执行的 guided SBY 任务可点击“迁移到 FormalMC”，在工具内部创建并打开关联工程。转换校验源运行与当前输入，目标从尚未运行开始。操作与边界见[内部迁移说明](12_formalmc_migration.md)。
